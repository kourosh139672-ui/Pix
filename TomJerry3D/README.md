# TomJerry3D — first-person Unity demo

A first-person Unity prototype: explore a connected house as Jerry while Tom patrols, spots the player and chases. The house and gameplay objects are generated by C# scripts.

## Quick start
1. Create a Unity 3D project (Unity 6 recommended).
2. Copy `TomJerry3D/Scripts` into `Assets/TomJerry3D/Scripts`.
3. Copy the contents of `TomJerry3D/Editor` into `Assets/Editor/`.
4. In Unity choose **Tools → Tom & Jerry 3D → Create Playable Demo Scene**.
5. Open `Assets/TomJerry3D/Scenes/TomJerryDemo.unity` and press Play.

Full steps, Android export and controls: [GAMEPLAY_SETUP.md](GAMEPLAY_SETUP.md).

## Included gameplay
- First-person mouse movement and camera look.
- Runtime Android HUD with movement joystick, swipe-look, objective/cheese counter and USE button.
- Start screen plus pause overlay with Resume and Restart controls.
- Procedurally generated connected house and runtime NavMesh.
- Procedural cartoon Tom and Jerry components, lightweight motion, and Tom patrol/sight/chase/search AI.
- Mission progression, generated sound cues and LOW / MED / HIGH graphics presets.
- Carry/drop items, kitchen fridge food dispenser and baitable mousetrap.
- Collectible cheese and cartoon prop chaos; Tom gets sent to the porch briefly after enough mess.

## Android APK export
1. Install **Android Build Support**, including SDK, NDK and OpenJDK, through Unity Hub.
2. Create the demo scene, then add `Assets/TomJerry3D/Scenes/TomJerryDemo.unity` to **File → Build Settings → Scenes In Build**.
3. Copy `TomJerry3D/Editor/TomJerryAndroidBuild.cs` into `Assets/Editor/`.
4. Run **Tools → Tom & Jerry 3D → Validate Project**, fix any reported missing setup, then run **Tools → Tom & Jerry 3D → Build Android APK**.
5. The helper writes `Builds/Android/TomJerry3D.apk` if Unity's Android toolchain is installed and the build succeeds.

The helper configures landscape orientation, IL2CPP and ARM64. It does not bypass Unity licensing or install Android modules for you.

## Status and limitations
This is a prototype, not a finished commercial game. Character and environment visuals are generated from Unity primitives; they are not high-detail skinned meshes or imported production assets. Animation is lightweight procedural motion, and audio cues are synthesized tones rather than recorded dialogue, music or polished sound effects. The project has not been compiled or play-tested in Unity in this repository workflow. No APK is included; a successful export must be performed in Unity Editor on a machine with Android Build Support.

Unity gameplay scripts use C#. Kotlin is only appropriate for separate native Android integrations, not for Unity scene gameplay.
